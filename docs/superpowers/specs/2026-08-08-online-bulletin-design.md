# 인터넷 주보 (Online Bulletin) — 설계

- 작성일: 2026-08-08
- 대상: 빌드업교회 홈페이지 (`~/websites/buildup-church`, 정적 HTML, GitHub Pages)

## 배경 및 목적

주일예배 순서지(주보)를 홈페이지에 매주 게시한다. 목회칼럼(`column/`)·주간묵상(`devotions/`)과
동일하게 순수 정적 HTML, 날짜별 폴더 + 목록 페이지 패턴을 그대로 따른다 — 새로운 도구나 빌드
시스템을 도입하지 않는다.

## 범위 밖

- 목사님이 직접 입력하는 관리 화면(별도 앱)은 이번 단계에서 만들지 않는다. 매주 이 대화에서
  목사님이 내용을 전달하면 어시스턴트가 페이지를 만들어 커밋한다. 추후 필요해지면 별도로
  `~/apps/buildup-church-admin`에 입력 화면을 추가하는 것을 재검토할 수 있다(이번 스펙의
  범위 아님).
- 성경 본문 자동 조회(성경 API 연동)는 하지 않는다 — 매주 목사님이 전달하는 개역개정 전문을
  그대로 타이핑해 넣는다.

## 구조

```
bulletin/
├── index.html                 # 주보 목록 (카드 목록, column/index.html과 동일한 패턴)
├── 2026-08-09/
│   ├── index.html             # 그 주 주보 본문
│   └── images/
│       └── (콘티/악보 사진 파일들)
├── 2026-08-16/
│   └── ...
```

- 폴더명은 예배일(주일) 날짜 `YYYY-MM-DD` 하나로만 구성한다 — column과 달리 매주 별도의
  주제 slug가 필요 없다.
- 사이트 상단 내비게이션(모든 페이지의 `<nav>`)에 "인터넷 주보" 링크를 "주일설교 영상" 다음,
  "주간 묵상" 앞자리에 추가한다 (예배 관련 항목들과 인접하도록).

## 페이지 구성 (한 주 `bulletin/YYYY-MM-DD/index.html`)

기존 `column/*/index.html`과 동일한 `<head>`/`<nav>`/폰트/색상 체계를 그대로 재사용한다
(Tailwind CDN, Font Awesome, Pretendard, 인디고 계열 포인트 컬러). 본문은 아래 8개 섹션을
순서대로, 카드 또는 구분선으로 나눈 세로 목록으로 구성한다:

1. **예배의 부름** — 묵도 안내 문구 + "인도자의 기도" + 인도자 이름
2. **찬양** — 곡 제목(들) + 콘티/악보 사진(`<img>`, `images/` 폴더 참조)
3. **대표기도** — 담당자 이름
4. **광고** — 자유 텍스트 목록(항목별 줄바꿈, 리스트 형태)
5. **성경봉독** — 본문 장절 표기 + 개역개정 전문 타이핑 + 봉독자 이름
6. **설교** — 설교 제목 + 설교자 이름
7. **기도** — 결단기도(통성)/마무리기도/헌금기도 3개 하위 항목, 각각 담당자 이름(선택)
8. **축도** — 담당자 이름

각 섹션은 제목(예: "1. 예배의 부름")과 내용을 명확히 구분해 보여주고, 담당자 이름은 섹션
제목 옆이나 아래에 작게 표기한다(예: `인도자: 홍길동 목사`).

## 목록 페이지 (`bulletin/index.html`)

`column/index.html`과 동일한 카드 그리드 패턴 — 각 카드는 예배일 날짜, 설교 제목(그 주
설교 제목을 대표 텍스트로 사용), "자세히 보기" 링크로 구성한다. 최신 주가 맨 위로 오도록
날짜 내림차순 정렬한다.

## 유지보수 흐름

1. 목사님이 이번 주 8개 항목 내용(+콘티 사진 파일)을 이 대화에서 전달
2. 어시스턴트가 `bulletin/YYYY-MM-DD/` 폴더와 `index.html`을 만들고, 콘티 사진을
   `images/`에 저장
3. `bulletin/index.html` 목록에 이번 주 카드를 새로 추가
4. 로컬 커밋 후, 실제 배포(`git push`)는 매번 목사님 승인을 받고 진행

## 테스트 방침

정적 HTML 페이지이므로 자동화 테스트는 두지 않는다. 매주 페이지 생성 후 브라우저에서 직접
열어 레이아웃과 링크가 정상인지 육안으로 확인한다(로컬 파일 열기 또는 배포 후 실제 URL 확인).
